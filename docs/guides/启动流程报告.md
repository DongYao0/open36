# Open436 项目启动流程报告

## 一、项目架构概览

Open436 教育平台采用**混合部署**架构：
- **Docker**：基础设施 + HOJ 判题系统 + FileService
- **本地运行**：Java 业务服务 + Python 服务 + 前端

### 服务清单

| 分类 | 服务名 | 端口 | 运行方式 | 说明 |
|------|--------|------|----------|------|
| **基础设施** | postgres | 55400 | Docker | 主数据库 |
| | redis | 6380 | Docker | 缓存 + Sa-Token Session |
| | consul | 8500 | Docker | 服务注册发现 |
| | kong + kong-db | 8000/8001 | Docker | API 网关 + satoken-auth 插件 |
| | minio | 9000/9001 | Docker | 对象存储 |
| | etcd | 2379 | Docker | Milvus 元数据存储 |
| | milvus-standalone | 19530 | Docker | 向量数据库（AI 服务依赖） |
| **HOJ 系统** | hoj-mysql | 3308 | Docker | HOJ 专用数据库 |
| | go-judge | 5050 | Docker | 代码执行沙盒 |
| | hoj-backend | 6688 | Docker | HOJ 后端 API |
| | hoj-judge | 8088 | Docker | 判题服务 |
| | hoj-vue | 8066 | Docker | HOJ 前端 |
| **业务服务** | auth-service | 8081 | 本地 java -jar | 认证服务 (Java Spring Boot) |
| | enrollment-service | 8084 | 本地 java -jar | 报名服务 (Java Spring Boot) |
| | forum-service | 8003 | 本地 python | 论坛服务 (Django) — 合并帖子/评论/板块 |
| | ai-service | 8008 | 本地 python | AI 智能服务 (FastAPI + Multi-Agent) |
| **Docker 业务** | file-service | 8007 | Docker | 文件服务 (Rust Actix-web) |
| **前端** | frontend | 3000 | 本地 npm | 用户前端 (Vue 3) |
| | admin | 3001 | 本地 npm | 管理后台 (Vue 3) |

## 二、启动流程

### 步骤 1：启动 Docker 基础设施 + FileService

```bash
docker compose up -d
```

等待所有服务健康：
```bash
docker compose ps
```

预期状态：
- postgres: `healthy`
- redis: `running`
- consul: `running`（leader elected）
- kong: `healthy`
- minio: `running`
- etcd: `healthy`
- milvus-standalone: `running`（健康检查可能显示 unhealthy，但服务可用）
- file-service: `running`

### 步骤 2：启动 HOJ 系统

```bash
docker compose --profile hoj up -d
```

验证：
```bash
# HOJ 后端 API
curl http://localhost:6688/api/get-problem-list

# HOJ 前端
curl -o /dev/null -w "%{http_code}" http://localhost:8066/algo/

# go-judge 沙箱
curl http://localhost:5050/version
```

**默认账号**：root / hoj123456

### 步骤 3：启动 Java 业务服务

**Auth 服务（认证）：**
```bash
cd Open436-Auth
java -jar target/Open436-Auth-0.0.1-SNAPSHOT.jar --spring.profiles.active=dev
```

**Enrollment 服务（报名）：**
```bash
cd Open436-Enrollment
java -jar target/Open436-Enrollment-0.0.1-SNAPSHOT.jar --spring.profiles.active=dev
```

验证：
```bash
curl http://localhost:8081/actuator/health
curl http://localhost:8084/actuator/health
```

**注意**：
- 使用 `dev` profile，配置文件为 `application-dev.yml`
- Redis 端口为 **6380**（Docker 映射）
- PostgreSQL 端口为 **55400**（Docker 映射）

### 步骤 4：启动 Forum 服务（Django）

Forum 服务合并了原来的 Content、Comment、Section 三个服务。

```bash
cd Open436-Forum
python manage.py runserver 0.0.0.0:8003
```

验证：
```bash
curl http://localhost:8003/health/
# 预期返回: {"status": "healthy", "database": "ok", "service": "forum-service", ...}
```

### 步骤 5：验证 FileService

FileService 已在步骤 1 中随 Docker 基础设施一起启动。

验证：
```bash
curl http://localhost:8007/health
# 预期返回: {"service":"file-service","status":"healthy"}
```

**注意**：首次启动需要构建镜像，耗时约 2-3 分钟。

### 步骤 6：启动 AI 智能服务

AI 服务依赖 Milvus 向量数据库（步骤 1 已启动）。

```bash
cd Open436-AIService
# 使用项目虚拟环境
venv\Scripts\python.exe -m uvicorn app.main:app --host 0.0.0.0 --port 8008
```

验证：
```bash
curl http://localhost:8008/health
# 预期返回: {"code":200,"data":{"status":"healthy","service":"ai-service","version":"1.0.0"}}
```

### 步骤 7：启动前端

**用户前端：**
```bash
cd Open436-Frontend
npm run dev
```

**管理后台：**
```bash
cd Open436-Admin
npm run dev
```

验证：
- 用户前端: http://localhost:3000
- 管理后台: http://localhost:3001

### 步骤 8：配置 Kong 路由

首次启动或 Kong 重启后需要配置路由：

```bash
bash deploy/dev/kong-config.sh
```

该脚本会：
1. 创建 auth-service 路由 → `/api/auth/*`
2. 创建 file-service 路由 → `/api/files/*` + satoken-auth 插件
3. 创建 enrollment-service 路由 → `/api/enrollment/*`
4. 创建 forum-service 路由 → `/api/posts/*`, `/api/comments/*`, `/api/sections/*` 等

## 七、已知问题

### 1. Milvus 健康检查失败

**现象**：`docker compose ps` 显示 milvus-standalone 为 `unhealthy`

**原因**：Milvus 健康检查端点路径与配置不匹配

**影响**：服务实际可用，仅健康检查显示异常

**解决**：可忽略，或修改 docker-compose.yml 中的健康检查配置

### 2. Auth 服务 Hibernate Schema 验证失败

**现象**：启动时报 `Schema-validation: wrong column type`

**原因**：数据库表字段类型与实体定义不匹配

**解决**：将 `application-dev.yml` 中的 `ddl-auto` 设置为 `update`

```yaml
spring:
  jpa:
    hibernate:
      ddl-auto: update  # 而非 validate
```

### 3. Redis 端口配置

**现象**：Java 服务无法连接 Redis

**原因**：Docker Redis 映射到 6380，但 Java 配置可能使用 6379

**解决**：确保 `application-dev.yml` 中 Redis 端口为 6380

```yaml
spring:
  data:
    redis:
      port: 6380
```

## 八、常用运维命令

### Docker 服务

```bash
# 查看容器状态
docker compose ps

# 查看服务日志
docker compose logs -f [服务名]

# 重启单个服务
docker compose restart [服务名]

# 停止所有 Docker 服务
docker compose --profile hoj down

# 停止并删除数据卷（危险！会清除数据）
docker compose --profile hoj down -v
```

### 本地服务

```bash
# Java 服务 - 使用 jar 包
cd Open436-Auth && java -jar target/Open436-Auth-0.0.1-SNAPSHOT.jar --spring.profiles.active=dev
```

```bash
# 查看所有服务
```

## 九、网络架构

```
浏览器
  ↓
localhost:3000 (Frontend - 本地 npm)
  ├── /           → Vue SPA
  ├── /api/auth/  → Kong:8000 → auth-service (本地 :8081)
  ├── /api/...    → Kong:8000 → 各业务服务
  └── /algo/      → hoj-vue:8066 → HOJ 前端 (Docker)

localhost:3001 (Admin - 本地 npm)
  ├── /           → Vue SPA
  ├── /api/ai/    → ai-service:8008 (本地)
  └── /api/hoj/   → hoj-backend:6688 (Docker)

Docker 网络 (open436-net: 172.28.0.0/16):
  ├── postgres (:55400), redis (:6380), consul (:8500)
  ├── kong (:8000), minio (:9000)
  ├── etcd, milvus-standalone (:19530)
  ├── file-service (:8007) — 随基础设施启动
  └── hoj-mysql (:3308), go-judge (:5050), hoj-backend (:6688), hoj-judge (:8088), hoj-vue (:8066) — 可选
```

## 十、快速启动脚本

### Windows (PowerShell)

```powershell
# 1. 启动基础设施 + FileService
docker compose up -d

# 2. 启动 HOJ（可选）
docker compose --profile hoj up -d

# 3. 启动 Java 服务（新终端）
Start-Process -FilePath "java" -ArgumentList "-jar", "Open436-Auth/target/Open436-Auth-0.0.1-SNAPSHOT.jar", "--spring.profiles.active=dev"
Start-Process -FilePath "java" -ArgumentList "-jar", "Open436-Enrollment/target/Open436-Enrollment-0.0.1-SNAPSHOT.jar", "--spring.profiles.active=dev"

# 5. 启动 Python 服务（新终端）
Start-Process -FilePath "python" -ArgumentList "Open436-Forum/manage.py", "runserver", "0.0.0.0:8003"
Start-Process -FilePath "python" -ArgumentList "-m", "uvicorn", "app.main:app", "--host", "0.0.0.0", "--port", "8008" -WorkingDirectory "Open436-AIService"

# 6. 启动前端（新终端）
Start-Process -FilePath "npm" -ArgumentList "run", "dev" -WorkingDirectory "Open436-Frontend"
Start-Process -FilePath "npm" -ArgumentList "run", "dev" -WorkingDirectory "Open436-Admin"

# 7. 配置 Kong 路由
bash deploy/dev/kong-config.sh
```

### Linux/Mac (Bash)

```bash
#!/bin/bash
# 1. 启动基础设施 + FileService
docker compose up -d

# 2. 启动 HOJ（可选）
docker compose --profile hoj up -d

# 3. 启动 Java 服务
cd Open436-Auth && java -jar target/Open436-Auth-0.0.1-SNAPSHOT.jar --spring.profiles.active=dev &
cd ../Open436-Enrollment && java -jar target/Open436-Enrollment-0.0.1-SNAPSHOT.jar --spring.profiles.active=dev &

# 3. 启动 Python 服务
cd ../Open436-Forum && python manage.py runserver 0.0.0.0:8003 &
cd ../Open436-AIService && venv/bin/python -m uvicorn app.main:app --host 0.0.0.0 --port 8008 &

# 4. 启动前端
cd ../Open436-Frontend && npm run dev &
cd ../Open436-Admin && npm run dev &

# 5. 配置 Kong 路由
cd .. && bash deploy/dev/kong-config.sh
```
