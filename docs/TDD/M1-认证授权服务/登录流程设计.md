## 🔐 登录流程详解

### 1. 用户登录流程

#### 1.1 前端发起登录

**文件**: `Open436-Frontend/src/stores/auth.js`

```javascript
async function login(username, password) {
  // 1. 调用登录接口
  const res = await request.post('/api/auth/login', { username, password })
  
  // 2. 保存 Token 和用户信息
  setToken(res.data.token)
  setUser(res.data.user)
  
  // 3. 同步到 HOJ 判题系统
  await syncToHoj()
  
  return { success: true }
}
```

#### 1.2 Kong 网关路由

**路由配置** (`deploy/dev/kong-config.sh`):

```bash
# Auth 服务路由
curl -X POST $KONG_ADMIN/services/auth-service/routes \
  --data "paths[]=/api/auth" \
  --data strip_path=false

# 认证插件（仅对需要鉴权的服务启用）
curl -X POST $KONG_ADMIN/services/file-service/plugins \
  --data name=satoken-auth \
  --data config.auth_service_url=http://host.docker.internal:8081
```

**说明**:
- `/api/auth/*` 路由直接转发到 Auth 服务，**不经过** satoken-auth 插件
- `/api/files/*` 等需要鉴权的路由会先经过 satoken-auth 插件验证 Token

**文件**: `Open436-Auth/src/main/java/com/open436/auth/service/impl/AuthServiceImpl.java`

```java
@Override
public LoginResponse login(LoginRequest request) {
    // 1. 认证用户（数据库操作，在事务中）
    UserAuth user = authenticateUser(request);
    String role = user.getPrimaryRoleCode();
    
    // 2. 创建会话（外部状态操作，不在事务中）
    String token = createSession(user.getId(), user.getUsername(), role);
    
    // 3. 返回结果
    return LoginResponse.builder()
        .token(token)
        .expiresIn(tokenProperties.getTimeout())
        .user(UserInfoResponse.from(user, role))
        .build();
}
```

#### 1.4 用户认证流程

```java
@Transactional
protected UserAuth authenticateUser(LoginRequest request) {
    // 1. 查询用户
    UserAuth user = userAuthRepository.findByUsername(request.getUsername())
        .orElseThrow(() -> new BusinessException(ErrorCode.INVALID_CREDENTIALS));
    
    // 2. 检查账号状态
    // pending 用户允许登录（游客模式，仅浏览权限）
    if (UserStatus.DISABLED.getCode().equals(user.getStatus())) {
        throw new BusinessException(ErrorCode.ACCOUNT_DISABLED);
    }
    
    // 3. 验证密码（BCrypt）
    if (!passwordEncoder.matches(request.getPassword(), user.getPasswordHash())) {
        throw new BusinessException(ErrorCode.INVALID_CREDENTIALS);
    }
    
    // 4. 更新最后登录时间
    user.setLastLoginAt(LocalDateTime.now());
    userAuthRepository.save(user);
    
    return user;
}
```

#### 1.5 创建 Sa-Token 会话

```java
private String createSession(Long userId, String username, String role) {
    // 1. 使用 Sa-Token 登录（自动生成 Token 并开启自动续签）
    StpUtil.login(userId, new SaLoginModel()
        .setDevice(TokenConstants.DEVICE_WEB)
        .setIsLastingCookie(true)
        .setTimeout(tokenProperties.getTimeout())  // 30天
    );
    
    // 2. 设置 Session 信息（存储在 Redis）
    StpUtil.getSession().set(TokenConstants.SESSION_KEY_USERNAME, username);
    
    // 3. 获取并返回 Token 值
    return StpUtil.getTokenValue();
}
```

### 2. Token 验证流程

#### 2.1 Kong 插件验证

**文件**: `deploy/dev/kong/plugins/satoken-auth/handler.lua`

```lua
function SaTokenAuthHandler:access(conf)
  -- 1. 获取 Token
  local token = kong.request.get_header(conf.token_header_name)
  if not token then
    return kong.response.exit(401, { message = "No token provided" })
  end
  
  -- 移除 "Bearer " 前缀
  token = token:gsub("Bearer ", "")
  
  -- 2. 调用认证服务验证 Token
  local verify_url = conf.auth_service_url .. "/api/auth/verify"
  local res, err = httpc:request_uri(verify_url, {
    method = "POST",
    headers = { ["Content-Type"] = "application/json" },
    body = cjson.encode({ token = token })
  })
  
  -- 3. 解析响应并注入用户信息到 Header
  local userData = body.data.data or body.data
  kong.service.request.set_header("X-User-Id", tostring(userData.userId))
  kong.service.request.set_header("X-Username", userData.username)
  kong.service.request.set_header("X-User-Role", userData.role)
  kong.service.request.set_header("X-User-Status", userData.status)
end
```

#### 2.2 Auth 服务验证 Token

**文件**: `Open436-Auth/src/main/java/com/open436/auth/controller/AuthController.java`

```java
@PostMapping("/verify")
public ResponseEntity<ApiResponse<TokenVerifyResponse>> verifyToken(
        @RequestBody TokenVerifyRequest request) {
    try {
        // 验证 Token
        Object loginId = StpUtil.getLoginIdByToken(request.getToken());
        
        if (loginId == null) {
            return ResponseEntity.ok(ApiResponse.success(new TokenVerifyResponse(false, null)));
        }
        
        // 获取用户信息
        Long userId = Long.parseLong(loginId.toString());
        
        // 切换到该用户的上下文来获取 Session
        StpUtil.switchTo(userId);
        String username = (String) StpUtil.getSession().get(TokenConstants.SESSION_KEY_USERNAME);
        String role = roleService.getUserRoleCodes(userId).stream()
            .findFirst().orElse("user");
        String status = userService.getUserStatus(userId);
        
        UserTokenInfo userInfo = new UserTokenInfo(userId, username, role, status);
        return ResponseEntity.ok(ApiResponse.success(new TokenVerifyResponse(true, userInfo)));
    } catch (Exception e) {
        return ResponseEntity.ok(ApiResponse.success(new TokenVerifyResponse(false, null)));
    }
}
```

### 3. 用户状态管理

#### 3.1 用户状态说明

| 状态 | 说明 | 登录权限 | 操作权限 |
|------|------|----------|----------|
| `pending` | 待审核（新注册用户） | ✅ 允许登录 | 仅浏览 |
| `active` | 正常用户 | ✅ 允许登录 | 完整权限 |
| `disabled` | 已禁用 | ❌ 禁止登录 | 无 |

#### 3.2 角色权限

| 角色 | 说明 | 权限范围 |
|------|------|----------|
| `user` | 普通用户 | 帖子、评论、个人资料 |
| `admin` | 管理员 | 用户管理、内容审核、系统配置 |

### 5. 会话管理

#### 5.1 Sa-Token 配置

**文件**: `Open436-Auth/src/main/resources/application.yml`

```yaml
sa-token:
  token-name: token
  timeout: 2592000        # 30天
  active-timeout: -1      # 永久有效（活跃期间）
  is-concurrent: true     # 允许同一账号并发登录
  is-share: true          # 多人登录共用一个 token
  token-style: uuid       # Token 风格
  is-log: false           # 不输出操作日志
  auto-renew: true        # 开启自动续签
```

#### 5.2 自动续签机制

```
初始Token：有效期30天（2592000秒）
  │
  ├─→ 5天后访问：剩余25天 > 15天（一半）→ 不续签
  │
  └─→ 16天后访问：剩余14天 < 15天（一半）→ 自动续签至30天
```

**续签时机**:
- 用户每次访问需要认证的接口时
- Sa-Token 检查 Token 剩余有效期
- 如果剩余有效期 < 续签时间的一半，则自动续签

#### 5.3 Redis 存储结构

```
Key: satoken:login:token:{tokenValue}
Value: {
  "id": "1",
  "loginId": "1",
  "username": "alice"
}
TTL: 自动续签会更新 TTL
```

### 6. 安全机制

#### 6.1 密码安全

- **加密算法**: BCrypt
- **密码验证**: `passwordEncoder.matches(rawPassword, encodedPassword)`

#### 6.2 Token 安全

- **存储位置**: Redis（服务端）+ LocalStorage（客户端）
- **传输方式**: `Authorization: Bearer {token}` Header
- **有效期**: 30 天（自动续签）
- **撤销机制**: 登出时清除 Redis Session

#### 6.3 防攻击措施

| 攻击类型 | 防护措施 |
|----------|----------|
| 暴力破解 | 登录失败次数限制（5次/小时） |
| Token 窃取 | HTTPS 传输 + HttpOnly Cookie（可选） |
| 会话固定 | 登录时生成新 Token |
| CSRF | Token 验证 + SameSite Cookie |
