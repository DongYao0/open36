# M1 - 认证与授权模块 PRD

## 模块概述

**模块名称**：认证与授权模块
**模块编号**：M1
**优先级**：P0（核心基础模块）
**目标用户**：全体系统用户（普通用户 + 管理员 + 访客）
**技术栈**：Spring Boot 3 + Sa-Token + JPA + PostgreSQL + Redis

### 业务目标

1. **身份识别**：确认"你是谁"——验证用户身份的真实性
2. **访问控制**：确认"你能做什么"——基于 RBAC 的权限控制
3. **跨系统认证**：与 HOJ 算法平台的 SSO 单点登录
4. **用户画像**：提供基础的用户资料与统计数据（供其他服务消费）

### 模块边界

> **职责范围**：本模块负责身份认证、权限控制、用户基础数据（账号+画像+统计）。
> 不涉及业务内容（帖子、评论、招新），但提供 Internal API 供其他服务查询/更新用户数据。

## 功能需求

### 1. 用户注册

#### 1.1 业务场景

新用户通过注册页面提交账号信息，系统创建账号后进入待审核状态（pending），管理员审核通过后账号激活。

#### 1.2 功能说明

| 项目 | 说明 |
|------|------|
| 接口 | `POST /api/auth/register` |
| 鉴权 | 无需登录 |
| 输入 | username, password, studentId, realName, phone, major |
| 输出 | 注册成功，账号状态为 `pending` |

#### 1.3 业务规则

- 用户名：3-20 字符，全局唯一
- 密码：6-32 字符，BCrypt 加密存储
- 注册后状态为 `pending`，需管理员审核激活
- 注册时自动创建 UserProfile 和 UserStatistics 记录
- 默认角色为 `user`，默认 clientPermission 为 `all`

#### 1.4 审核流程

管理员通过 `PUT /api/auth/users/{id}/status` 将状态改为 `active`，或使用 `POST /api/auth/users/{id}/activate-and-sync` 一键激活并同步到 HOJ。

### 2. 用户登录

#### 2.1 业务场景

用户使用用户名和密码登录系统，获取 Sa-Token 凭证。

#### 2.2 功能说明

系统提供两个登录接口：

| 接口 | 路径 | 说明 |
|------|------|------|
| 普通登录 | `POST /api/auth/login` | 所有用户可用 |
| 管理员登录 | `POST /api/auth/admin/login` | 仅 admin 角色可用，非 admin 返回 403 |

#### 2.3 业务规则

**登录流程**：
1. 根据用户名查找用户
2. 检查账号状态：
   - `disabled` → 拒绝，提示"账号已被禁用"
   - `pending` → 允许登录（作为访客，功能受限）
   - `active` → 正常登录
3. BCrypt 验证密码
4. 更新 `lastLoginAt`
5. 调用 `StpUtil.login(userId, "web")` 创建 Sa-Token Session
6. 在 Session 中存储 `username`
7. 返回 token 和用户信息

**Token 配置**：

| 配置项 | 值 | 说明 |
|--------|-----|------|
| token-name | `token` | HTTP Header 名称 |
| timeout | 2592000s (30天) | Token 有效期 |
| active-timeout | -1 | 无活跃超时 |
| auto-renew | true | 活跃时自动续期 |
| is-concurrent | true | 允许并发登录 |
| is-share | true | 共享 Token |
| token-style | uuid | UUID v4 格式 |

**安全规则**：
- 用户名不存在和密码错误统一提示"用户名或密码错误"（防信息泄露）
- 登录成功后返回 `token`（UUID 字符串）和 `user` 对象
- 前端通过 `token` HTTP Header 传递凭证

#### 2.4 登录响应格式

```json
{
  "code": 200,
  "message": "登录成功",
  "data": {
    "token": "a9ab167c-6ddb-4b47-a15b-bc865f7421b4",
    "expiresIn": 2592000,
    "user": {
      "id": 1,
      "username": "admin",
      "role": "admin",
      "status": "active",
      "clientPermission": "all"
    }
  }
}
```

|------|------|
| 接口 | `POST /api/auth/logout` |
| 鉴权 | `@SaCheckLogin` |

#### 4.1 功能说明

| 项目 | 说明 |
|------|------|
| 接口 | `GET /api/auth/current` |
| 鉴权 | `@SaCheckLogin` |
| 输出 | 当前登录用户的完整信息（含角色） |

### 7. 用户管理（管理员）

#### 7.1 用户列表

| 项目 | 说明 |
|------|------|
| 接口 | `GET /api/auth/users?status=active` |
| 鉴权 | `@SaCheckRole("admin")` |
| 可选参数 | `status`（pending/active/disabled），不传返回全部 |

#### 7.2 创建用户

| 项目 | 说明 |
|------|------|
| 接口 | `POST /api/auth/users` |
| 鉴权 | `@SaCheckRole("admin")` |
| 输入 | username, password, role, studentId, realName, phone, major, clientPermission |

业务规则：
- 用户名唯一性校验
- 角色必须存在（admin/user/viewer）
- clientPermission 校验：`all`/`forum`/`quiz`/`none`，默认 `all`
- 创建后自动建立 UserProfile 和 UserStatistics

#### 7.3 更新用户状态

| 项目 | 说明 |
|------|------|
| 接口 | `PUT /api/auth/users/{id}/status` |
| 鉴权 | `@SaCheckRole("admin")` |
| 输入 | `status`（pending/active/disabled） |

业务规则：
- 禁用（disabled）或待审核（pending）时，踢出该用户所有设备
- 启用（active）后用户可正常登录
- 不删除用户数据

#### 7.4 更新用户角色

| 项目 | 说明 |
|------|------|
| 接口 | `PUT /api/auth/users/{id}/role` |
| 鉴权 | `@SaCheckRole("admin")` |
| 输入 | `role`（admin/user/viewer） |

业务规则：
- 清除所有旧角色，设置单一新角色（实质单角色设计）
- 自动映射 clientPermission：admin→all, user→all, viewer→forum
- 清除角色和权限缓存

#### 7.5 更新用户权限

| 项目 | 说明 |
|------|------|
| 接口 | `PUT /api/auth/users/{id}/permission` |
| 鉴权 | `@SaCheckRole("admin")` |
| 输入 | `clientPermission`（all/forum/quiz/none） |

#### 7.6 删除用户

| 项目 | 说明 |
|------|------|
| 接口 | `DELETE /api/auth/users/{id}` |
| 鉴权 | `@SaCheckRole("admin")` |

业务规则：
- 踢出用户 → 清除缓存 → 删除记录（CASCADE 删除关联数据）
- 级联删除：user_roles、user_profile、user_statistics、hoj_user_mapping

#### 7.7 批量操作

| 接口 | 说明 |
|------|------|
| `DELETE /api/auth/users/batch` | 批量删除，body 为 ID 数组 |
| `PUT /api/auth/users/batch/status` | 批量更新状态 |
| `POST /api/auth/users/batch-info` | 批量查询用户信息（admin 专用） |

### 10. HOJ SSO 同步

#### 10.1 业务场景

管理后台用户点击"算法管理"时，自动将用户同步到 HOJ 并获取 HOJ JWT Token，实现免登录跳转。

#### 10.2 功能说明

| 项目 | 说明 |
|------|------|
| 接口 | `POST /api/auth/algo-sync` |
| 鉴权 | `@SaCheckLogin` |
| 输出 | HOJ JWT Token（在响应体 data 字段中） |

#### 10.3 同步流程

1. 验证用户状态必须为 `active`
2. 获取用户角色
3. POST 请求 HOJ 后端 `/api/open436-sync`：
   ```json
   {
     "username": "admin",
     "nickname": "管理员",
     "avatar": null,
     "apiKey": "open436-secret-key",
     "role": "admin"
   }
   ```
4. 从 HOJ 响应的 `Authorization` Header 提取 JWT Token
5. 从响应体提取 HOJ uid，保存 `hoj_user_mapping` 映射
6. 返回 HOJ Token 给前端

#### 10.4 前端集成流程

```
Admin 侧边栏点击"算法管理"
  → 调用 /api/auth/algo-sync 获取 HOJ Token
  → 存入 localStorage.setItem('token', hojToken)
  → window.location.href = "http://localhost:8066/algo/admin/dashboard?hoj_token=xxx&username=xxx&role=xxx"
  → HOJ 前端 beforeEach 读取 URL 参数，存入 localStorage
  → 进入 HOJ 管理后台
```

## 权限控制（RBAC）

### 角色定义

| 角色 | 角色标识 | 说明 | 默认 clientPermission |
|------|---------|------|----------------------|
| 普通用户 | `user` | 可发帖、回复、互动 | all |
| 管理员 | `admin` | 拥有全站管理权限 | all |
| 访客 | `viewer` | 只读权限 | forum |
| （待审核） | — | 注册后未审核，功能受限 | all |

### 权限矩阵

系统使用 `resource:action` 格式的权限码，初始数据包含 8 个权限：

| 权限码 | 说明 | user | admin | viewer |
|--------|------|------|-------|--------|
| `user:read` | 查看用户信息 | ✅ | ✅ | ✅ |
| `user:create` | 创建用户 | ❌ | ✅ | ❌ |
| `user:update` | 编辑用户 | ❌ | ✅ | ❌ |
| `user:delete` | 删除用户 | ❌ | ✅ | ❌ |
| `user:manage` | 管理用户状态 | ❌ | ✅ | ❌ |
| `role:read` | 查看角色 | ✅ | ✅ | ❌ |
| `role:manage` | 管理角色 | ❌ | ✅ | ❌ |
| `system:manage` | 系统配置 | ❌ | ✅ | ❌ |

### clientPermission（客户端权限）

独立于 RBAC 的二级权限控制，控制用户可访问的客户端模块：

| 值 | 说明 |
|----|------|
| `all` | 访问所有模块（论坛+算法+管理） |
| `forum` | 仅论坛模块 |
| `quiz` | 仅算法模块 |
| `none` | 无客户端权限 |

## 安全需求

### 1. 密码安全

| 项目 | 实现方式 |
|------|---------|
| 加密算法 | BCrypt（cost factor = 10） |
| 存储格式 | `{bcrypt}$2a$10$...` |
| 最小长度 | 6 字符 |
| 最大长度 | 32 字符 |

### 2. Token 安全

| 项目 | 当前实现 | PRD 要求 |
|------|---------|---------|
| Token 格式 | UUID v4 | ✅ |
| 有效期 | 30 天 | ⚠️ PRD 原文写 2 小时，实际 30 天 |
| 传输方式 | HTTP Header `token` | ✅ |
| 存储位置 | 前端 localStorage（带 `open436_admin_` 前缀） | ✅ |
| 自动续期 | Sa-Token auto-renew=true | ✅ |

### 3. 防暴力破解

| 项目 | 状态 |
|------|------|
| 登录失败次数限制 | ⚠️ 配置已定义（5次/3600s），代码未实现 |
| IP 级别限流 | ⚠️ 未实现 |
| 验证码 | ⚠️ 未实现 |

### 4. CORS 配置

| 来源 | 允许 |
|------|------|
| `http://localhost:3000` | ✅ 论坛前端 |
| `http://localhost:3001` | ✅ 管理后台 |
| `http://localhost:3005` | ✅ |
| `http://localhost:8080` | ✅ |

> ⚠️ 注意：`application.yml` 中的 CORS 配置与 `CorsConfig.java` 不一致，Java 配置优先。

## 已知问题与待办

### 🔴 安全问题（需修复）

| # | 问题 | 严重程度 | 说明 |
|---|------|---------|------|
| S1 | ProfileController 缺少鉴权 | 高 | `PUT /api/users/{id}/profile` 和 `POST /api/users/{id}/avatar` 无 @SaCheckLogin 注解，任何人可修改他人资料 |
| S2 | Internal API 无认证 | 中 | `/internal/users/*` 无鉴权，依赖网络隔离。建议增加服务间 Token 校验 |
| S3 | 登录防暴力破解未实现 | 中 | `security.max-login-attempts` 配置存在但代码未读取 |

### 🟡 功能缺陷（需完善）

| # | 问题 | 说明 |
|---|------|------|
| F1 | 头像上传为 Stub | `UserProfileServiceImpl.uploadAvatar()` 仅保存占位路径，未调用 M7 文件服务 |
| F2 | 注册昵称未传递 | `RegisterRequest.nickname` 字段存在但未使用，profile 默认昵称为"用户{id}" |
| F3 | 无忘记密码流程 | 缺少邮箱验证和密码重置流程 |
| F4 | 无邮箱通知 | 注册审核、密码重置等操作无通知机制 |

### 🟢 设计决策（已确认）

| # | 决策 | 说明 |
|---|------|------|
| D1 | 实质单角色设计 | DB 支持多角色（ManyToMany），但业务层每次只设一个角色 |
| D2 | Token 30 天有效期 | Sa-Token timeout=2592000s，auto-renew=true，活跃用户永不过期 |
| D3 | pending 状态可登录 | 待审核用户可登录但功能受限，需管理员激活 |
| D4 | 角色缓存 30 分钟 | userRoles 和 userPermissions 缓存在 Redis，变更时主动清除 |
